# Figma画面仕様

> 最終更新日: 2026-09-21

## 目的

この文書は、Figmaで検討した主要画面と操作仕様を記録する。プロダクト要求の正本は `docs/vision.md` とし、Figmaは画面構成と操作を視覚的に確認するための編集可能な資料として扱う。

## デザインファイル

- [MomentPalette（Figma）](https://www.figma.com/design/K2tfDw1Wj9pQJ2heFbh7FJ/MomentPalette?node-id=0-1&t=P4QjS9z2QLy0duFM-1)

現時点の見た目は暫定である。画面一覧と各画面の責務を基準として利用し、具体的な配置、余白、色、アイコン、文字サイズは、操作可能なVueプロトタイプとモバイル実機で検討・調整する。

## 主要画面

| フレーム | 主な責務 |
| --- | --- |
| `Title` | アプリの開始、言語切替、バージョン表示 |
| `SelectTempate` | テンプレート一覧の表示と選択 |
| `Coloring` | エリア選択、三つの塗り方の選択、作品の確定 |
| `Coloring-BackComfirm` | 制作途中で戻る場合の確認 |
| `Camera-frameON` / `Camera-frameOFF` | カメラ撮影、作品と全体スルー映像の表示比率調整 |
| `Album-select` | OSの写真ライブラリ・撮影・ファイル選択UIの呼び出し |
| `Album-adjust` | 選択した写真の位置、倍率、作品との表示比率の調整 |
| `Color-pallete` | 選択中エリアへ設定する単色の選択 |
| `Complete` / `Share` | 統合済みPNGの確認、長押し保存、OS共有シートの呼び出し |

フレーム名の誤記や実装上の命名は、Vueプロトタイプへそのまま引き継ぐ必要はない。

## 制作画面

### エリア選択

- 選択枠は画面中央へ固定し、エリアの選択肢をその背後で横スクロールさせる。
- 一覧は無限ループさせず、先頭から末尾まで移動できるようにする。
- 初期選択は先頭エリアとし、先頭項目を中央の選択枠へ配置する。
- 先頭と末尾を中央へ配置できるよう、一覧の両端に余白を設ける。
- スクロール終了時は最も近い項目を中央へスナップし、その時点で選択を確定する。
- 中央以外の項目をタップした場合も、その項目を中央へ移動して選択する。
- 隣の項目を一部見せ、横へ操作できることが視覚的に伝わるようにする。

### 塗り方

- `OMOIDE`（思い出から切り取る）: 写真ライブラリ、OSカメラ、ファイルから画像を選ぶ。
- `KESHIKI`（景色から切り取る）: アプリ内カメラのスルー映像から撮影する。
- `KOKORO`（気持ちからつくる）: カラーパレットから単色を選ぶ。
- 設定済みエリアも、三つの方法のいずれかで何度でも上書きできる。
- 初期リリースでは、未着色の初期状態へ戻す専用のリセット操作を設けない。

## カメラ・写真の調整

### 表示比率スライダー

- 現在の作品と、カメラ全体のスルー映像または選択した写真全体との表示比率を連続的に調整する。
- 0%では、写真や初期カラーを隠し、元映像または元写真と線画を表示する。
- 100%では現在の作品を表示し、選択中エリア内だけに元映像または元写真を表示する。
- 中間では、構図と作品の色合いを比較するため両者を重ねて表示する。
- どの比率でも選択中エリアの元映像または元写真は薄くせず、不透明な状態を保つ。
- 初期値は100%とする。
- 両端の星アイコンをタップすると、0%または100%へ直接移動する。
- 星アイコンは現時点のデザインを維持し、実装後の試用で意味が伝わりにくい場合に差し替える。

### ジェスチャー

- 線画と映像または写真を表示する正方形全体を編集領域とする。
- 編集領域内から始めた1本指ドラッグで位置を移動する。
- 2本の指を編集領域内へ置いて始めたピンチで拡大・縮小する。
- 操作開始後は、指が編集領域の外へ移動しても操作を継続する。
- スライダー、シャッター、完了、キャンセル、カメラ切替などの操作部品から始めたジェスチャーは、画像操作として扱わない。
- 編集領域へ局所的なタッチ制御を適用し、ジェスチャーがブラウザのページスクロールやページズームに奪われないようにする。
- カメラ映像は、映像のない余白が選択中エリアへ入らないよう倍率と移動範囲を制限する。
- 端末から選んだ写真は形式によって操作を分けず、初期のcover表示から縮小して画像外の余白を残したまま確定できるようにする。
- 写真の透明部分と画像外の余白には選択中エリアの初期カラーを表示し、重なっている別エリアの画像を透けさせない。

### カメラ切替

- 初回は背面カメラを使用する。
- 前面と背面を利用できる場合は、右下の切替ボタンをタップするたびに切り替える。
- 前面カメラはプレビューと撮影結果をどちらも左右反転し、鏡像の見え方を揃える。
- 一方しか利用できない場合は切替ボタンを表示しない。
- 初期リリースでは、超広角、標準、望遠などの背面レンズを個別に選ぶUIを設けない。

### 選択中エリアの輪郭

- 不透明部分と完全透過部分から成るPNGマスクをもとに、前処理スクリプトで輪郭画像を生成できる設計を検討する。
- 一つのマスクに離れた複数の形状が含まれる場合も、すべてを同じ選択エリアとして扱う。
- 輪郭表示は初期リリースの必須要件ではなく、他の主要機能より優先度を下げる。

## 完成確認と共有

- `Coloring`から`Complete`へ移る時点で、各エリアと線画を1080×1080の一枚のPNGへ統合する。
- `Complete`では、統合済みPNGを画像要素として表示する。
- `Complete`から`Coloring`へ戻って作品を変更した場合は、以前のPNGを破棄し、次の遷移時に再生成する。
- 完成画面には「画像を長押しして保存できます」という案内を表示する。
- 独自のPNGダウンロードボタンは設けない。
- `SHARE`は統合済みPNG、固定文、ハッシュタグ、アプリURLをOS共有シートへ渡す。
- OS共有シートから写真へ保存できるかどうかは、OSとブラウザの提供機能に従う。
- 「もういちど遊ぶ」で新しい制作を始めるときは、最新バージョンの確認を行う。

## プロトタイプで確認すること

- 中央固定のエリア選択が、項目数や形状が異なるテンプレートでも操作しやすいか。
- 表示比率スライダーと星アイコンの意味が、説明なしで伝わるか。
- 1本指移動とピンチズームが、iPhone Safari、iPhone Chrome、Android Chromeで自然に動作するか。
- 小さいエリアや離れた複数形状を持つエリアで、輪郭表示がなくても選択対象を認識できるか。
- 完成PNGの長押し保存と、OS共有シートから写真へ保存する操作が、正式対応環境で利用できるか。
