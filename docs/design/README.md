# 画面設計資料

## 目的

このディレクトリには、Moment Paletteの画面遷移、ワイヤーフレーム、操作状態、ビジュアル方針を保存する。プロダクト要求の正本は `docs/vision.md` とし、このディレクトリは要求を視覚化し、実装前に操作性を検証するために使用する。

## 現在のデザイン

- [MomentPalette（Figma）](https://www.figma.com/design/K2tfDw1Wj9pQJ2heFbh7FJ/MomentPalette?node-id=0-1&t=P4QjS9z2QLy0duFM-1)
- 合意済みの画面構成と操作仕様は [`figma.md`](figma.md) に記録する。

現在のFigmaは、画面の責務、主要導線、操作方法を確認するための基準とする。具体的な余白、配色、アイコン、コントロールの大きさなどは確定デザインではなく、操作可能なVueプロトタイプとモバイル実機で調整する。Figmaと `docs/vision.md` が食い違う場合は、要求の正本である `docs/vision.md`を優先する。

## 保存するもの

- 画面一覧と画面遷移。
- 手描きラフの整理結果。
- 低精度・高精度ワイヤーフレーム。
- Figmaファイルへの参照と確認用エクスポート。
- 通常、読み込み中、権限要求、拒否、エラーなどの画面状態。
- 配色、余白、タイポグラフィ、アイコンなどのデザイン判断。
- モバイル実機で確認した結果。

## 保存しないもの

- 実行可能なVue、HTML、CSS、JavaScriptコード。
- 技術F/Sのコードや結果。
- Azureアーキテクチャ図。

操作可能なコードプロトタイプを作る場合は、OpenSpec changeを作成し、そのchangeの範囲内で管理する。

## 予定する構成

```text
docs/design/
├── README.md
├── screen-flow.md
├── ui-states.md
├── figma.md
└── exports/
```

必要になった時点でファイルを追加する。エクスポート画像だけを正本にせず、元のFigmaファイルまたは編集可能なソースへの参照を残す。

## 初期の検討対象

1. タイトル画面。
2. テンプレート選択画面。
3. 制作画面。
4. カメラ撮影画面。
5. 写真選択・位置調整画面。
6. カラーパレット画面。
7. 完成確認・共有画面。
8. カメラ権限、横向き、共有非対応などの補助画面。

画面設計で新しい要求や矛盾が見つかった場合は、`docs/vision.md`へ反映する。
